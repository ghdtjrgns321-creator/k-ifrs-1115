# 진입 흔들림 통로 분해 — 실험 기록 (2026-07-27)

같은 질문을 반복해도 검색 문단이 달라지는 원인을 통로별로 가른다.
재현: `PYTHONPATH=. uv run python app/test/qna_holdout/exp_entry_variance.py`
분모 = dev-with-gold **57건**, 입력 = `exp_baseline.json`(3회 기록). **LLM 호출 0**.

## 배경

`retrieve` 구간은 순수 함수다. 그래프 순회도 MongoDB 조회도 진입 순서를 보존한다.
그런데도 결과가 흔들리므로, 원인은 그 앞의 `analyze`에 있다.

`analyze`는 그래프에 값을 두 개 넘긴다(`app/nodes/analyze.py:56-59`).

| 통로            | 값                 | 그래프에서 하는 일                                        |
| --------------- | ------------------ | --------------------------------------------------------- |
| (a) 주제 지목   | `topic_hints`      | `topic_map` 조회 → `via_topic` → `_adaptive_subtree` 확장 |
| (b) 질문 재작성 | `standalone_query` | `resolve_terms` substring 매칭 → 개념·사례                |

(b)는 결정적 함수인데 **입력이 LLM 생성문**이다. 재작성이 단어 하나만 달라져도 걸리는
용어가 바뀐다.

## 분해 방법

`concept_ids` = `via_topic` + 확장 + `resolve_terms`. 앞 둘은 기록된 `via_topic`만
있으면 결정적으로 재계산되므로, 나머지(residual)가 (b)의 몫이다.

전제 검사를 먼저 통과시켰다 — 지금 온톨로지로 재계산한 확장 집합이 캡처본
`concept_ids`에 **161/161 포함**. 순서 불일치 135건은 `_subtree` 수정(35225c3) 탓이라
집합 비교에는 무해하다.

> 온톨로지 파일은 캡처 시점(2026-07-08)에 untracked였고 2026-07-14에 통째로 추가됐다.
> git 대조가 불가능해 동일성은 위 집합 포함으로만 확인했다.

## 결과 3 — 잃는 것이 무엇인가

잃은 정답개념은 한쪽에 몰려 있다.

```
   14회  수행의무의 이행

```

뒤집힌 4건은 전부 상황 서술형 질문이고, 원문에는 "수행의무"라는 말이 없다.

| 케이스            | 원문 사전매칭                    |
| ----------------- | -------------------------------- |
| QNA-SSI-202312052 | `계약`                           |
| QNA-SSI-202412003 | `계약`                           |
| QNA-SSI-202412044 | `계약`, `독점판매권`, `지적재산` |
| QNA-SSI-202412045 | `유상사급`                       |

예: "반도체 장비 제작이 6개월~1년 걸리고 계약금·중도금·잔금으로 받는데…" →
정답개념은 `기간에 걸쳐 이행하는 수행의무` / `한 시점에 이행하는 수행의무`.
재작성이 이 상황을 5단계 모형 용어로 **번역**해줬기 때문에 사전이 걸렸다.

이건 단어 치환이 아니라 판단이다. 별칭 사전을 넓혀도
"장비 제작 6개월, 계약금·중도금·잔금" → "기간에 걸쳐 이행하는 수행의무"는 만들 수 없다.

또 하나: 이 4건에서 같은 LLM이 **주제 지목으로는 수행의무를 못 짚었는데 재작성으로는
짚었다.** 재작성 통로는 사실상 주제 지목의 예비 경로로 작동하고 있다.

## 종합 — 흔들림과 품질은 같은 원천이다

세 실험이 모두 같은 벽에 부딪혔다.

| 시도             | 결과                        | 막힌 이유                                 |
| ---------------- | --------------------------- | ----------------------------------------- |
| 재작성문 제거    | 결정성 2.3배, 정답 4건 손실 | 재작성이 구어→전문용어 번역을 하고 있었다 |

README §10이 진입 불안정을 결함으로만 서술한 것은 절반만 본 것이다 — 이 절의 결론을
README에 반영해야 한다.

# 결과 8 — 보조 진입(코사인 후순위 병합) 구현 후 실측

`exp_aux_entry.py` · dev 57건 · 회차1 진입에 코사인 top-3을 뒤에 붙여 대조.
`via_topic`·용어사전 몫은 양쪽 동일하므로 보조 진입만의 효과가 분리된다.

새로 붙은 개념은 케이스당 평균 0.95개(중복 제외 후).

| | 개념 | 문단 | hit | 커버리지 |
| --- | --- | --- | --- | --- |
| 보조 없음 | 13.2 | 88.4 | 54/57 (94.7%) | 79.6% |
| 보조 있음 | 14.2 | 99.0 | **55/57 (96.5%)** | **83.6%** |

| | MRR | 중앙 | @5 | @10 | @20 | @50 | 전멸 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 보조 없음 | 0.498 | 3 | 61.4% | 73.7% | 82.5% | 91.2% | 3 |
| 보조 있음 | 0.498 | 3 | 61.4% | 73.7% | 82.5% | 91.2% | **2** |

**문단 순위 지표가 전부 동일하다.** 후보 맨 뒤에 붙이는 설계라 앞 순위를 건드리지 않는다는
의도가 실측으로 확인됐다. 얻은 것은 hit +1건·커버리지 +4.0%p·전멸 −1건, 대가는 회수 문단
88.4→99.0개(+12%)다.

hit +1은 `exp_decision.md`가 2026-07-07에 측정한 Δ+1과 같은 크기다. 재채택 사유가 성능이
아니라는 판단은 그대로 유효하다.

## 구현 형태

- 진입 순서: `topic_hints`(1순위) → 용어사전(2순위) → **코사인 top-3(안전망, 맨 뒤)**
- 질의 텍스트는 **사용자 원문** — 재작성문은 회차마다 달라 이 통로까지 흔들리게 만든다
  (`exp_decision.md`의 코사인 실측도 원문 기준이었다)
